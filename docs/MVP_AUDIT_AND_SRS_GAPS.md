# MVP backend audit and SRS gaps

This report reviews the current backend checkout against [the English rewrite of the supplied improvement notes](IMPROVEMENTS.md) and [the VideoScript SRS](VIDEOSCRIPT_SRS.md). The original `improvements.txt` remains outside this repository at `D:/Coding/Working/Projects/VideoScript/Docs/improvements.txt`. The source notes and SRS are reference material, not instructions to change code or proof of working features. This is a static review; PostgreSQL and external services have not been exercised end to end. The frontend is in another repository, so the FE entries below are requirements to check or implement, not findings about the current FE.

### Non-functional and technology requirements to settle in the SRS

- The SRS target of processing a video under one minute long within 60 seconds has no measurement conditions or SLA. [ShotStackVideoServiceImpl](../src/main/java/com/suplerteam/video_creator/service/video/ShotStackVideoServiceImpl.java) can wait two minutes just for rendering. Specify input size, percentile, third-party conditions, and timeout behavior visible to FE.
- Clarify what “encrypted information” covers: passwords use BCrypt in [SecurityConfig](../src/main/java/com/suplerteam/video_creator/security/SecurityConfig.java), while OAuth tokens need a separate storage/key-management policy. Require ownership checks, OAuth state validation, TLS, and secret-free logs.
- The SRS names Java Spring + Python microservices and PostgreSQL + MongoDB. The present repository is a Spring Boot service using PostgreSQL according to [pom.xml](../pom.xml) and [docker-compose.yaml](../docker-compose.yaml). Mark the additional architecture as a future target or a required MVP deliverable.
- The SRS asks for “free” third-party NLP/TTS models but gives no selection criteria. Define quotas, quality, cost, terms, and fallback; do not assume third-party APIs remain free.
- Add success, empty-result, external-API failure, timeout, authorization, and FE display criteria for each F1–F7 feature. Label unimplemented items as gaps rather than current product capabilities.

## 4. Proposed implementation order

1. Close authorization and disclosure paths: I01–I06 and I20, especially OAuth state, workspace ownership, and media URLs.
2. Make a fresh checkout runnable: I07–I09, I21, N01, N04, migrations, configuration, and clean-database tests.
3. Correct rendering, uploads, and analytics: I10–I19 and N02–N03, with job states and failure tests.
4. Finalize F1–F7 MVP scope, implement selected gaps, then update README and regression tests.

Validation limit: `mvnw.cmd -o -q test` did not finish during the earlier review and was stopped, so no passing or failing build is claimed. Database and external-service behavior has not been tested.
